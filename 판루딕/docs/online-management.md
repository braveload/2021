# 온라인 세션·방·요청 관리 · 2026-11-21

기존 작업 분기 codex/panludiq-design-schema, 기존 두 Render 서비스 사용. 홈페이지는 feature 배포 분기, 온라인 서버는 main 수동 배포다. main 최신 내용을 기반으로 서버 관련 커밋만 반영하고, 규칙 엔진·승패·연결 끊김 15초 감지/60초 1회 유예는 바꾸지 않는다.

1. 서버: 유효 세션 재사용, 유휴 세션 10분 정리, 대기/완료 방 정리, 세션별 요청 제한·정상 전달 헤더를 신뢰하지 않는 익명 입장 보호·Retry-After. 상한은 안전장치로 유지한다. 로컬 가짜 시계와 HTTP 검사.
2. 브라우저: 재접속 핸드셰이크, 오류 복구, 요청 제한/장애 때 점진 재시도. 로컬 두 브라우저 생성/참가/준비/이동/재접속/퇴장.
3. 서버 커밋 main 반영 후 수동 배포, 홈페이지 배포. 실제 두 브라우저에서 동일 검사. 증거와 재개 정보 기록.

한계: 메모리 서버와 현재 무료 서비스는 유지하며, DB/유료 플랜/다중 인스턴스를 추가하지 않는다. 서버 재시작 시 방이 초기화되는 기존 제약은 유지된다. 실제 사이트 대량 부하를 보내지 않는다.

## 1단계 완료

세션 상한 3,000개·방 상한 500개는 보호 장치로 유지했다. 세션은 마지막 인증 이후 10분 만료, 유효 토큰 POST 재사용과 현재 미완료 방 복구 코드를 지원한다. 대기 방은 2분 이상 연락 없는 참가자를 정리해 준비 상태를 초기화하고, 빈 방은 삭제한다. 완료 방은 모두 퇴장하거나 2분간 모두 연락이 없을 때/완료 30분 후 정리한다. 대전 중 15초 감지·60초 1회 복귀와 미니 체스 엔진은 그대로다.

요청 제한: 유효 세션별 조회 120회/분, 변경 60회/분, 핸드셰이크 20회/분. 신규 브라우저 식별자는 인증 용도가 아닌 익명 생성 남용 방지용이며 12회/분. 구버전은 연결 주소 기준 120회/분, 전체 신규 생성은 300회/분 안전장치. 인증 실패 요청은 연결 주소 기준 1,200회/분. 유효한 다른 사용자는 같은 프록시 주소여도 제한을 공유하지 않는다. 임의 X-Forwarded-For는 신뢰하지 않는다. 최대 16,000개 제한 항목과 만료 정리, 429 Retry-After·CORS 노출 지원. 유료 자원 추가 없음.

로컬 관리 검사와 기존 대전 검사 통과: 3,005회 재사용, 유휴 정리/진행 게임 보호, 만료 후 신규 토큰, 방 슬롯 회수, 준비 초기화, 퇴장·재대결 제한, 제한 버킷 상한/만료, 동일 소켓 주소의 서로 다른 인증 세션 분리, 위조 전달 헤더 무효, 익명 입장 전체 제한. 승패·합법 이동·중복 이동·연결 복구·재대결 선후공 기존 검사 통과.

다음: 이 서버 변경을 origin/main 최신 위에 반영해 기존 수동 배포 서비스를 갱신한다. 홈페이지 기능 분기에는 이후 브라우저 복구와 자동 검사만 추가한다. 원격 main 변경 여부를 확인하고 강제 푸시는 하지 않는다.
